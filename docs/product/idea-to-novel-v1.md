# Idea-to-Novel V1 — 产品 1.0 纵向切片规格

> Status: ACCEPTED
> Effective date: 2026-08-03
> Authority: 依据 `/PRODUCT_DIRECTION.md`（Idea-to-Novel Product Direction V1）
>
> 本文档定义产品 1.0 的纵向切片规格：从用户输入模糊想法，到生成至少一个完整章节，再到修改、继续生成与导出的端到端能力。
>
> - 旧文档若描述 Grill-first、Contract-first 或纯 Writer-first 流程，以 `/PRODUCT_DIRECTION.md` 为准；
> - 本文档聚焦产品 1.0 能力范围，工程实现细节由 roadmap / architecture 文档承载。

---

## 6.1 用户入口

产品 1.0 的默认入口是：

```text
告诉我你想写什么
```

入口支持：

```text
自由文本
多轮补充
跳过问题
直接粘贴已有设定
选择目标作品形式
```

- 自由文本：用户用一句话或一段话描述初始想法；
- 多轮补充：用户可以在访谈过程中继续补充想法；
- 跳过问题：用户可以不回答某个问题直接继续；
- 直接粘贴已有设定：用户已有完整设定时，可以跳过大部分追问；
- 选择目标作品形式：用户选择希望生成的作品形式（如短篇、长篇章节、特定文体等）。

编辑器不是产品 1.0 唯一入口；对已有项目，系统按状态返回想法、调研、规划、生成或稿件阶段。

## 6.2 Idea Intake V1

Idea Intake（创作访谈）是产品 1.0 的核心资产，采用自然对话形式。

### 抽取用户已表达的信息

系统需要从用户的初始想法中抽取已经表达的信息，包括：

- 题材与类型；
- 目标读者；
- 篇幅或章节目标；
- 作品形式；
- 叙事视角；
- 基调；
- 节奏；
- 语言偏好；
- 必须包含的内容；
- 必须避免的内容；
- 内容边界；
- 生成方式。

### 缺失信息才值得追问

- 只有对创作结果有实质影响、且用户尚未表达的信息才值得追问；
- 无关紧要的字段不追问，进入默认值或留空；
- 追问数量应尽可能少。

### 如何结束访谈

- 系统判断已有信息足以形成可编辑创作要求时，可以结束访谈；
- 用户主动结束访谈；
- 用户粘贴已有设定后直接结束；
- 用户连续跳过问题时，系统不再追问。

### 如何生成可编辑 CreationSpec

访谈结束后，系统将抽取的信息整理为可编辑创作要求（CreationSpec），至少包含：

```text
题材与类型
目标读者
篇幅或章节目标
作品形式
叙事视角
基调
节奏
语言偏好
必须包含
必须避免
内容边界
生成方式
```

### 用户如何修改要求

- CreationSpec 以可编辑形式呈现；
- 用户可以直接修改任意字段；
- 修改后的 CreationSpec 是后续调研、蓝图与生成的权威输入；
- 内部可保留结构化 snapshot 和版本思想，但不以审批、字段锁或契约完成门禁作为主体验。

### 不暴露给用户的内容

- session 状态机；
- question-plan proposal；
- task / invocation；
- contract 完成度；
- 数据库和 Token 状态。

## 6.3 Web Research V1

Web Research 是产品 1.0 的一级能力。

### 调研触发判断

调研强度由以下因素决定：

- 题材是否依赖现实事实；
- 用户是否要求真实性；
- 是否涉及具体时代、地域、职业或事件；
- 现有输入是否已经足够；
- 调研成本与创作收益。

三档调研强度：

```text
无需调研
轻量调研
深度调研
```

### 调研问题计划

- 系统生成调研问题计划；
- 用户可查看调研问题计划；
- 用户可增加、删除或跳过问题。

### 搜索来源与来源记录

- 执行搜索并记录每个来源；
- 来源记录保留可追溯信息；
- 来源错误时允许用户删除或排除。

### 事实笔记

- 调研结果整理为事实笔记；
- 事实笔记与来源关联；
- 事实笔记供生成阶段注入使用。

### ResearchBundle

- 调研问题计划、来源、事实笔记与结论汇总为 ResearchBundle；
- 生成时只注入与当前创作相关的调研内容；
- 不需要在 1.0 设计复杂知识图谱。

## 6.4 Story Blueprint V1

系统基于创作要求（与必要调研）设计故事蓝图（StoryBlueprint），至少包含：

```text
核心前提
主角与关键人物
主要关系
世界背景
主要冲突
结局方向
主要情节线
章节结构
每章目标
```

- 蓝图以可编辑形式呈现，用户可修改；
- 蓝图是章节生成的结构性输入；
- 蓝图属于权威用户数据，AI 不能静默覆盖。

## 6.5 Generation V1

章节生成流程：

```text
章节目标
→ 内部场景计划
→ 分场景生成
→ 章节组合
→ 基础检查
→ 定点修订
→ 写入稿件
```

- Scene Planner 在 1.0 中是生成流水线的内部能力，不要求先做成独立复杂产品页面；
- 生成结果写入稿件（Manuscript）；
- 写入稿件前保留用户手写正文，不静默覆盖；
- 每次生成作为一次 GenerationRun 记录，便于用户理解与控制。

---

## 6.6 Manuscript V1

稿件（Manuscript）按章组织，支持：

```text
章节目录
正文查看和编辑
重新生成章节
局部重写
继续生成下一章
修改后续方向
TXT 和 Markdown 导出
```

- 正文编辑器是稿件阶段的主要界面；
- 用户手写正文不会被生成结果静默覆盖；
- 用户原始想法不会丢失；
- 应用重启后能够恢复最近工作。

---

## 6.7 非目标

产品 1.0 明确不包含：

```text
多人实时协作
无人值守生成整部长篇
复杂知识图谱
高级故事线 DAG
全面偏好学习
完整审计 UI
PlotPilot 强依赖
复杂版本 merge
自动发表
```

这些能力不得阻塞产品 1.0 的纵向链路构建。

## 6.8 产品验收标准

产品 1.0 的端到端验收：

```text
用户只输入一段模糊想法
→ 系统进行少量必要追问
→ 判断并执行适当调研
→ 形成可编辑创作要求与故事蓝图
→ 按指定形式生成至少一个完整章节
→ 用户可修改、继续生成并导出
```

验收时同时确认最低安全线：

```text
用户原始想法不会丢失
用户手写正文不会被生成结果静默覆盖
应用重启后能够恢复最近工作
```
