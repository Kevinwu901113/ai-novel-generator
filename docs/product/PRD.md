# 产品需求文档（PRD）

## 产品定位

AI 小说创作代理是一款中文优先、本地优先、采用 BYOK（Bring Your Own Key）模式的桌面应用，主要面向成人向同人网文创作。

核心价值主张：从模糊想法到完整小说，AI 代理全程辅助，但用户始终拥有最终控制权。

## 主路径

1. **想法输入**：用户提供模糊的创作想法
2. **Grill-me 需求澄清**：AI 通过多轮对话帮助用户明确需求
3. **原作和人物资料研究**：AI 辅助收集和整理参考资料
4. **创作契约**：用户与 AI 达成创作共识
5. **规划**：生成章节大纲和写作计划
6. **样稿与正文生成**：AI 生成初稿，用户审阅修改
7. **多轮审稿和定点修复**：AI 辅助审稿，用户确认修改
8. **导出**：支持 TXT、Markdown、DOCX 格式导出

## V1.0.0 范围

### 核心功能

- 项目创建与管理
- Grill-me 需求澄清流程
- 创作契约草案生成
- 基础人物和世界观管理
- 章节规划
- 正文生成（样稿 + 正文）
- 基础审稿和定点修复
- 版本管理与回滚
- 多格式导出

### 模型管理

- 支持多个 AI 提供商（OpenAI、Anthropic 等）
- 支持多模型配置
- 任务—模型映射（不同任务使用不同模型）
- Token 和费用统计

### 数据管理

- 本地 SQLite 存储
- 项目状态和任务状态分离
- 正文、契约、规划和状态版本化
- 用户文字默认受保护
- API Key 不进入项目备份

## Grill-me

Grill-me 是横向能力，贯穿整个创作流程：

- 不是简单的问答，而是深度需求挖掘
- AI 主动提问，帮助用户发现盲点
- 支持多轮对话，逐步澄清
- 结构化记录澄清结果

## 创作契约

创作契约是用户与 AI 的共识文档：

- 记录用户的核心需求和偏好
- 明确 AI 的创作边界
- 作为后续生成的约束条件
- 支持版本化和修订

## 状态管理

### 项目状态

- idea → grill-me → research → contract → planning → drafting → reviewing → completed

### 任务状态

- pending → in-progress → blocked → completed → failed

### 状态分离原则

- 项目状态反映整体进度
- 任务状态反映具体工作项
- 两者独立更新，通过 ChangeSet 关联

## 生成与审稿

### 生成流程

1. 基于创作契约和规划生成样稿
2. 用户审阅样稿，提出修改意见
3. AI 根据反馈生成正文
4. 支持定点修复和局部重写

### 审稿机制

- AI 自动审稿（一致性、逻辑、文风）
- 用户手动审稿
- 多轮迭代直到满意
- 审稿历史可追溯

## 模型管理

### 多提供商支持

- 统一接口，屏蔽提供商差异
- 支持动态切换模型
- 记录每个任务使用的模型

### 成本控制

- Token 用量统计
- 费用估算
- 上下文压缩减少 Token 消耗
- 缓存复用降低成本

## 本地优先

- 所有数据存储在本地 SQLite
- 不依赖云服务（除 AI API 调用）
- 项目备份包含所有必要数据
- API Key 单独管理，不进入备份

## 验收目标

V1.0.0 的首要验收目标：

**完成一篇高质量中文短篇**

具体标准：

- 从想法到成文的完整流程
- 用户体验流畅
- 生成质量达到可发布水平
- 版本管理和回滚正常工作
- 多格式导出正确

架构必须为长篇能力保留空间，但 V1 聚焦短篇验收。
