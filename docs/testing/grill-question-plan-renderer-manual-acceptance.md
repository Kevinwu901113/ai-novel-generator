# Grill 问题规划 Renderer 手工验收文档

本文档覆盖 Grill 问题规划工作流的手工验收测试用例。

---

## 前置条件

- 应用已启动并加载完成
- 已创建至少一个项目
- 已配置模型提供商

---

## 1. 创建项目并选择 Grill Session

1. 打开应用，创建新项目或选择现有项目
2. 进入 Grill-me 页面
3. 在左栏创建新会话或选择现有会话
4. 确认中栏显示会话面板和问题列表
5. **预期**：问题规划区域显示"请求问题规划"按钮

---

## 2. 键盘请求问题规划

1. 使用 Tab 键导航到"请求问题规划"按钮
2. 按 Enter 或 Space 键触发请求
3. **预期**：
   - 按钮变为"请求中…"并显示 disabled 状态
   - 按钮设置 `aria-busy="true"`
   - 请求完成后显示任务状态区域

---

## 3. 任务状态显示（PENDING/RUNNING）

1. 请求成功后，观察任务状态区域
2. **预期**：
   - 显示"问题规划任务"标题
   - 显示任务短 ID
   - 初始状态为"排队中"（PENDING）
   - 状态区域设置 `role="status"`
   - 标题获得焦点（focus-visible 样式可见）
3. 等待任务开始执行
4. **预期**：
   - 状态变为"执行中"（RUNNING）
   - 显示轮询指示器（⏳）
   - `aria-busy` 为 `true`

---

## 4. 成功提案显示

1. 任务完成后，观察提案列表
2. **预期**：
   - 状态变为"已完成"（SUCCEEDED）
   - 显示"问题规划提案"标题
   - 提案标题获得焦点
   - 显示提案卡片，包含：
     - 状态标签（"待审核"）
     - 问题数量
     - 基础版本
     - Schema 版本
     - 创建时间
   - 显示规划问题列表

---

## 5. Dependency 展示

1. 查看规划问题的依赖信息
2. **预期**：
   - `existing` 依赖显示"已有问题"标签，带问题 ID
   - `planned` 依赖显示"计划问题"标签，带问题 key
   - 两种类型有不同颜色区分
   - 不依赖数组顺序，按依赖类型正确分类

---

## 6. VoiceOver 测试

1. 启用 VoiceOver（macOS）
2. 使用 VoiceOver 导航到问题规划区域
3. **预期**：
   - 请求按钮可读："请求问题规划，按钮"
   - 任务状态可读："问题规划任务，标题"
   - 状态标签可读："排队中"、"执行中"等
   - 提案卡片可读：问题数量、状态
   - 接受按钮可读："接受此规划，按钮"

---

## 7. 显式接受

1. 在提案卡片中，点击"接受此规划"按钮
2. **预期**：
   - 按钮变为"接受中…"并显示 disabled 状态
   - 接受成功后，提案列表刷新
   - 正式问题列表刷新，包含新问题
   - 会话信息刷新
   - 焦点移动到正式问题区域或第一条新增问题

---

## 8. 接受后正式问题出现

1. 接受成功后，查看中栏问题列表
2. **预期**：
   - 新问题出现在问题列表中
   - 问题状态为"待提问"（PLANNED）
   - 问题 topic、text、rationale 正确显示
   - 依赖关系正确

---

## 9. Stale 提案

1. 等待提案变为 stale 状态（或模拟）
2. **预期**：
   - 提案显示"已过期"标签
   - 状态标签为"已废弃"
   - 接受按钮 disabled
   - 提案内容仍可阅读
   - stale 状态有可读文本，不只依赖颜色

---

## 10. Version Conflict

1. 在接受前，通过其他操作更新会话版本
2. 尝试接受提案
3. **预期**：
   - 显示错误："会话已在其他操作中更新，数据已自动刷新"
   - 正式问题列表不被篡改
   - 错误使用 `role="alert"`
   - 只有一个 alert

---

## 11. FAILED 任务

1. 模拟任务失败（如模型配置错误）
2. **预期**：
   - 状态变为"失败"
   - 显示安全错误码
   - 不显示原始错误信息
   - 不包含路径、stack trace 等敏感信息

---

## 12. Session 切换

1. 在任务进行中切换到另一个 session
2. **预期**：
   - 旧任务状态消失
   - 旧轮询停止
   - 新 session 的问题规划区域重置
   - 不显示旧 session 的数据

---

## 13. Task Center 交叉验证

1. 在任务活动中心查看问题规划任务
2. **预期**：
   - 任务 ID 与问题规划面板显示的一致
   - 任务状态同步
   - 可在任务活动中心查看详情

---

## 14. 无敏感信息

1. 检查所有显示的错误信息
2. **预期**：
   - 不包含 `/Users/` 路径
   - 不包含 Windows 绝对路径
   - 不包含 SQL 语句
   - 不包含 stack frame
   - 不包含 `Bearer ` token
   - 不包含 `sk-` API Key
   - 不包含原始 provider response body
   - 不包含完整内部 UUID

---

## 15. 焦点顺序

1. 使用 Tab 键导航整个问题规划区域
2. **预期**：
   - 焦点顺序合理：请求按钮 → 任务状态 → 提案列表 → 接受按钮
   - focus-visible 样式在所有交互元素上可见
   - 不出现焦点陷阱
   - polling rerender 不重复移动焦点

---

## 16. 按钮状态

1. 检查各种状态下的按钮
2. **预期**：
   - 无 session 时：请求按钮 disabled，显示提示
   - session 非 ACTIVE 时：请求按钮 disabled，显示提示
   - 请求期间：按钮 disabled，aria-busy
   - 轮询期间：请求按钮 disabled
   - 接受期间：接受按钮 disabled，aria-busy
   - stale 提案：接受按钮 disabled

---

## 17. 重复点击防护

1. 快速多次点击"请求问题规划"
2. **预期**：
   - 只发起一次请求
   - 不出现重复任务

3. 快速多次点击"接受此规划"
4. **预期**：
   - 只发起一次接受请求
   - 不出现重复接受

---

## 18. 页面可见性

1. 在任务轮询期间切换到其他标签页
2. 等待一段时间后切换回来
3. **预期**：
   - 页面隐藏时暂停轮询
   - 页面重新可见时立即刷新任务状态
   - 不丢失任务进度
