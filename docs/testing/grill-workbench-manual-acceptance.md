# Grill-me 工作台人工验收指南

从空应用开始的完整验收流程。每步包含操作、预期 UI、预期 version 变化和失败记录栏。

---

## 前置条件

- 应用已启动，无任何项目
- macOS Keychain 已配置（或使用 mock provider）

---

## 1. 创建项目

**操作**：点击"创建项目"，输入名称 `验收测试`，初始想法 `测试 Grill-me 功能`，确认。

**预期 UI**：项目列表出现"验收测试"，状态为"进行中"。

**预期 version 变化**：无（项目无 version 概念）。

- 左栏出现新 session，显示"探索角色动机"和"草稿"状态

- "启动"按钮可见

## 4. 添加两个问题

**操作**：

1. 点击"添加问题"，输入主题 `角色背景`，内容 `主角的童年经历是什么？`，理由 `理解角色动机`，确认
2. 再次点击"添加问题"，输入主题 `情节冲突`，内容 `核心冲突是什么？`，理由 `确定主线`，确认

**预期 UI**：

- 中栏问题列表出现两个问题
- 每个问题显示"待提问"状态
- 每个问题有"提问"、"跳过"、"废弃"按钮

**预期 version 变化**：每次添加后 version +1（3 → 4）。

## 11. 创建 proposal

**操作**：

1. 点击第一个问题（已回答的）
2. 在右栏"推理提案"区域点击"创建提案"
3. 输入 Key: `character.motivation`，Value: `{"drive":"保护弱者"}`，置信度: 0.8，理由: `基于回答推理`
4. 点击"确认创建"

**预期 UI**：

- 提案列表出现新提案
- 显示 key、JSON 值、置信度、理由
- 状态为"待审核"
- "接受"和"拒绝"按钮可见

**预期 version 变化**：session version +1（11）。

## 13. 暂停和恢复

**操作**：

1. 点击"暂停"按钮
2. 验证 UI 变化
3. 点击"恢复"按钮

**预期 UI（暂停后）**：

- 状态变为"已暂停"
- "暂停"按钮消失，"恢复"按钮出现
- "添加问题"按钮不可见
- 问题操作按钮不可见

**预期 UI（恢复后）**：

- 状态变回"进行中"
- "暂停"按钮重新出现
- "添加问题"按钮重新可见

**预期 version 变化**：暂停 +1（13），恢复 +1（14）。
