# Renderer 无障碍人工验收文档

## 环境要求

- macOS（推荐最新版本）
- 应用以开发模式运行（`pnpm dev`）

---

## 1. 全键盘控制

### 前置条件

- 系统设置 → 键盘 → 导航 → 勾选"使用键盘导航在控制间移动焦点"

### 操作

1. 打开应用
2. 使用 Tab 键浏览所有可交互元素
3. 使用 Shift+Tab 反向浏览

### 预期结果

- Tab 顺序：工具栏按钮 → 项目列表按钮 → 中栏内容 → 右栏内容
- 焦点轮廓清晰可见（蓝色边框 + 阴影）
- 不会跳过任何可交互元素

### VoiceOver 预期朗读

- "收起项目列表，按钮"
- "AI 小说创作代理，标题"
- "测试项目一，按钮"

## 2. VoiceOver 启动

### 前置条件

- 按 Cmd+F5 启动 VoiceOver

### 操作

1. 使用 VO+→（右箭头）浏览页面区域
2. 使用 VO+U 打开区域列表

## 3. 面板展开/收起

### 前置条件

- 应用已打开，左右面板可见

### 操作

1. Tab 到左栏切换按钮
2. 按 Enter 收起左栏
3. 按 Enter 展开左栏
4. Tab 到右栏切换按钮
5. 按 Enter 收起右栏
6. 按 Enter 展开右栏

### 预期结果

- 按钮 aria-expanded 从 true 变为 false
- 面板消失后不占空间
- 再次按 Enter 面板恢复

### VoiceOver 预期朗读

- "收起项目列表，按钮，已展开"

## 9. TaskCenter polling 时焦点不跳动

### 前置条件

- 有正在运行的任务（PENDING 或 RUNNING）
- 任务列表正在 polling

### 操作

1. 选择一个任务
2. 等待 2-4 秒（让 polling 触发 1-2 次）
3. 观察焦点是否跳动

### 预期结果

- 焦点保持在当前选中的任务上
- 不会突然跳到列表开头或其他位置
- 选中状态保持不变

### VoiceOver 预期朗读

## 13. Error Boundary fallback 与重新加载

### 前置条件

- 模拟某个区域崩溃（如 Grill 工作台）

### 操作

1. 触发区域崩溃
2. 观察 fallback 显示
3. Tab 到"重新加载此区域"按钮
4. 按 Enter 重新加载

### 预期结果

- fallback 容器获得焦点（tabindex=-1）
- 显示固定错误消息（不显示原始异常）
- "重新加载此区域"按钮可键盘操作
- 重新加载后焦点进入恢复的区域

## 15. 确认没有朗读完整 ID、路径、stack 或 API Key

### 前置条件

- 应用已打开
- VoiceOver 已启动

### 操作

1. 浏览项目列表（检查是否朗读完整项目 ID）
2. 浏览任务列表（检查是否朗读完整任务 ID）
3. 浏览错误消息（检查是否朗读路径或 stack）
4. 浏览 Provider 区域（检查是否朗读 API Key）

### 预期结果

- 项目名称朗读，不朗读完整 UUID
- 任务短 ID 朗读（前 8 字符），不朗读完整 UUID
- 错误消息为中文安全文本，不包含路径或 stack
- API Key 内容不被朗读

### VoiceOver 预期朗读

- "测试项目一，按钮"（不是 "proj-00000001-aaaa-bbbb-cccc-dddddddddddd"）
- "任务 task-0000，模型调用测试，成功"（不是完整 UUID）
- "创建项目失败"（不是 "/Users/foo/bar.ts:10:5"）

## 16. 全局状态公告

### 前置条件

- 应用已打开

### 操作

1. 触发全局错误（如创建项目失败）
2. 观察 VoiceOver 是否自动朗读错误
3. 等待数据服务状态变化
4. 观察状态公告

### 预期结果

- 全局错误使用 role="alert"，VoiceOver 自动朗读
- 数据服务状态使用 role="status"，不打断当前朗读
- 不会重复朗读相同内容

### VoiceOver 预期朗读

- 错误时："创建项目失败，警报"
- 状态变化时（不打断）："数据服务就绪"
