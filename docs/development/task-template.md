# 任务模板

## 任务描述模板

```markdown
## 任务：[任务标题]

### 背景

[简要描述任务背景和动机]

### 目标

- [ ] 目标 1
- [ ] 目标 2
- [ ] 目标 3

### 范围

**包含**：

- 功能点 1
- 功能点 2

**不包含**：

- 排除项 1
- 排除项 2

### 技术方案

#### 架构设计

[描述架构设计]

#### 数据模型

[描述数据模型]

#### 接口设计

[描述接口设计]

### 实现步骤

1. [ ] 步骤 1
2. [ ] 步骤 2
3. [ ] 步骤 3

### 测试要求

- [ ] 单元测试
- [ ] 集成测试
- [ ] 端到端测试（如需要）

### 验收标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] 标准 3

### 依赖

- 依赖 1
- 依赖 2

### 风险

- 风险 1：[描述] → [应对措施]
- 风险 2：[描述] → [应对措施]

### 参考

- [链接 1]
- [链接 2]
```

## 任务状态

- **待处理**：任务已创建，等待开始
- **进行中**：任务正在进行
- **阻塞**：任务被阻塞，等待依赖完成
- **已完成**：任务已完成
- **已失败**：任务失败，需要人工干预

## 任务优先级

- **P0**：阻塞性问题，必须立即解决
- **P1**：重要功能，优先处理
- **P2**：普通功能，按计划处理
- **P3**：低优先级，有空再处理

## 任务估时

- **S**：1-2 小时
- **M**：半天到一天
- **L**：2-3 天
- **XL**：一周以上

## 任务分配

- 每个任务有明确的负责人
- 任务可以有多个协作者
- 任务状态变更需要通知相关人员

## 任务跟踪

- 使用 Git commit 关联任务
- 使用 PR 关联任务
- 定期更新任务状态

## 完成定义（DoD）

任务完成必须满足：

1. 代码完成
2. 测试通过
3. 文档更新
4. 代码审查通过
5. 无已知 Bug
