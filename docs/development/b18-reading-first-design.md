# B18 设计：阅读优先——正文排版规范化与移动端成稿修复

> 背景：D12（B14–B17）完成 Tailwind 迁移与还债后，2026-08-17 对合并后基线做了一轮
> 结构化设计评审（桌面明暗 × 首页/四阶段/任务中心/设置/编辑器 + 375pt 移动视口）。
> 本批取评审结论中「核心场景受损」的部分：读小说正文的排版、移动端成稿阶段的布局
> 崩坏、两处与产品能力不符的文案。后续批次（读写分离 B19、信息密度 B20）另行设计。

## 1. 评审中坐实的问题（本批范围）

1. **正文行宽失控、阅读排版无规范**：候选正文容器 `max-w-[820px]`，16px 默认字号下
   一行约 50 个汉字（中文长文舒适区间是 35–42 字/行）；字号/行高/颜色散落在各消费点
   （候选 `leading-loose`、编辑器 `text-sm leading-[1.8]`、13px 简介行混杂），没有一个
   「小说正文」的排版权威。
2. **375pt 视口成稿阶段布局崩坏**（B17b 的 390px 实测漏了这两屏）：
   - 章节列表行（ChapterListRow）：`flex items-center` 一行里，右侧阶段文案
     `whitespace-nowrap` + 按钮为固定内容宽，内容区仅剩 ~241pt（rail 75 + clamp 内边距
     56）时，`min-w-0 flex-1` 的标题列被压到 **0 宽**，中文逐字竖排（实测坐实）；
   - 稿件头部行：`justify-between` 下「未命名稿件」同因竖排，「导出 Markdown」按钮
     溢出视口被裁切。
3. **移动端 rail 占用 20% 横向空间**：76px 常驻左栏在 375pt 屏上没有对应收益，
   顶栏标题与模型芯片双双截断。
4. **文案与产品能力不符**：
   - ProjectReadyPanel（B8 时代文案）仍说「逐章生成正文的功能还在开发中」——GE-6/GE-7
     已上线一个月，正是本项目「空承诺文案」教训的反面典型（方向相反但同罪：能力已有
     而文案说没有）；
   - ResearchRegion 回看横幅无条件承诺「以下是本项目当前的调研结果」，与同屏的
     「调研还没有开始。」并存（跳过调研的项目回看时自相矛盾）。

**评审更正记录**（相对 2026-08-17 口头评审报告）：① 正文 13px 的测量误中章节简介行
（`text-[13px]` goal 行），候选正文本体是 16px 继承——行宽/规范缺失结论不变，字号结论
修正；② 「编辑无自动保存」不成立——TD-033-3 已于 2026-08-15 由独立草稿层（v20/v21）
解决，B19 范围相应缩小。

## 2. 决策

### D-B18-1 阅读排版组件类 `.reading-prose`

`tailwind.css` 新增 components 层组件类，作为小说正文的唯一排版权威：

```css
@layer components {
  .reading-prose {
    max-width: 40em; /* CJK 下 1 字 ≈ 1em，约 40 字/行 */
    font-size: 17px;
    line-height: 1.9;
    color: var(--foreground);
    overflow-wrap: break-word;
  }
}
```

- 选组件类而非散装 utility：正文排版是**一组不可拆散的约束**（行宽依赖字号才有
  「字/行」语义），散装会重演「各消费点漂移」。
- 消费点（本批）：CandidateView 正文段落容器、ManuscriptPanel 正文 textarea（编辑
  与阅读同规格，字数直觉一致）。行宽约束由 `.reading-prose` 自持，外层 820px 布局
  上限保留（卡片壳与决策面板仍用）。
- 17px/1.9 的依据：中文屏显长文惯例区间（17–18px、1.8–2.0）取下缘，与现有 UI 的
  14/16px 层级拉开一档但不突兀；不引入新字体栈。

### D-B18-2 成稿两处 flex 行换行化

- ChapterListRow：`flex-wrap` + 标题列 `basis-48`（12rem）——宽度充足时单行不变，
  不足时标题占满整行、阶段文案与按钮换到第二行；阶段文案去 `whitespace-nowrap`
  （换行化后不再需要，保留会把第二行也撑溢出）。
- 稿件头部行与稿件章节行同法（`flex-wrap`，标题 `min-w-0`）。
- 不为 375pt 单独写分支：换行化在任何「标题特别长/视口特别窄」的组合下都是正确
  行为，比断点分支少一类失效模式。

### D-B18-3 移动端导航收纳（<768px）

- App 外层 grid 改响应式：`grid-cols-[minmax(0,1fr)] md:grid-cols-[76px_minmax(0,1fr)]`；
  AppRail `hidden md:flex`。
- 新增 `AppBottomNav`（AppRail.tsx 内同文件导出，复用 rail 配色 token 与按钮语义）：
  首页/新建/设置三项，横排、每项 min-h 48px 触控目标、`pb-[max(10px,env(safe-area-inset-bottom))]`，
  作为主列 flex 尾部的 `shrink-0` 行（不用 fixed 覆盖，不与内部滚动容器抢 z 轴）。
  `md:hidden`，桌面不渲染视觉。
- 顶栏模型芯片 `hidden md:inline-flex`——移动端入口由底部「设置」承接，芯片在窄屏
  本就退化成图标独木，信息量为零还占位。
- 四个 Region 与 HomePage 的内容内边距 clamp 下限 28px→16px（34px→20px），把省出的
  宽度还给正文；桌面端 clamp 上限不变，视觉不受影响。

### D-B18-4 文案更正

- ProjectReadyPanel：有章节数时改为「蓝图规划了 N 章。去上方『成稿』阶段逐章生成
  正文，每章生成完由你确认。」；无章节数分支同语义缩句。文件头「尚未接线，不放
  按钮」的注释一并更正（能力已上线；跳转按钮涉及 App 导航接线，留给 B20 信息密度批，
  本批只让文案不再说谎）。
- ResearchRegion 回看横幅按「是否真有调研资料」分文：`ready`/`stale` 保留原承诺；
  其余相位改为「创作旅程已进入后续阶段。本项目没有留下调研资料。」，且回看态下
  `no-run`/`not-started` 的正文行改为过去时陈述「本项目没有进行过调研。」（原文
  「调研还没有开始。」是未来时，在已越过调研的项目里误导）。

## 3. 不做什么（本批边界）

- 不动 JourneyNav 的绿勾语义（跳过的调研也计已到达——是否该区分「跳过」与「完成」
  是旅程语义问题，评审记录在案，非本批）；
- 不做只读阅读视图与编辑器高度自适应（B19）；
- 不动任务中心、项目卡信息密度、设置抽屉排序（B20）；
- 不加蓝图章节列表的「开始写」跳转（需要 App 级导航接线，并入 B20 一起设计）。

## 4. 验证基线

- 既有测试全绿（`pnpm check`）；涉及旧文案的断言随行更新；
- 浏览器实测：375pt 下成稿章节列表/稿件头不再竖排、导出按钮不溢出、底部导航可用；
  桌面 1280px 下候选正文行宽 ≈40 字、视觉无回归；明暗两色各过一遍关键屏。
