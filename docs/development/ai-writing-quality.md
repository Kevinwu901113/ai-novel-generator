# AI 创作篇幅与中文质量门

> 状态：已实现（2026-08-14）。本文件记录运行时规则、已验证边界和后续真实模型 A/B 方法。

## 1. 用户语义

CreationSpec 把三个容易混淆的量分开：

| 用户要求     | 权威字段                                    | 示例           |
| ------------ | ------------------------------------------- | -------------- |
| 全书总字数   | `targetLength: { unit: "words", value }`    | 全书 20 万字   |
| 全书章节数   | `targetLength: { unit: "chapters", value }` | 一章完结       |
| 单章正文篇幅 | `chapterLength`                             | 单章 15,000 字 |

“一共一章、单章 15,000 字”必须抽取为：

```json
{
  "targetLength": { "unit": "chapters", "value": 1 },
  "chapterLength": { "targetCharacters": 15000 }
}
```

蓝图严格生成一章。内部调用次数不能改变产品语义：用户最终看到一章、一个候选，采用后写入一个
ChapterVersion。单章目标允许 500–40,000 字；用户可在创作要求面板修改或清空。旧 CreationSpec 若仍在
`structure` 保存“每章约 3000 字”等文本，执行器继续兼容读取，并在下一次模型抽取时升级成结构化字段。

## 2. 字数口径

- 按去除空白后的 Unicode 字符数计算，不把 token、UTF-16 code unit 或文件字节数冒充“字数”；
- 用户给明确范围时严格使用 `minimumCharacters..maximumCharacters`；
- 只给“约 N 字”时使用 `90%N..110%N`，为不同题材和模型保留有限浮动；
- Requirement Critic 的模型判断之外再做一次确定性核验。越界必定是 major 且触发改写，模型不能用
  `pass` 绕过；
- 不用重复描写或空泛抒情补字数。达到范围与文学质量是两条独立门槛。

## 3. 长章节生成

目标不高于 5,000 字时沿用单次正文调用；更长时以约 3,200 字为一个内部片段：

1. Scene Planner 先看到完整目标篇幅，并按目标配置场景颗粒度；
2. Draft 按相邻场景分配片段；场景少于片段数时显式标注同一场景的第 N/M 部分；
3. 后续片段携带前文最后 1,200 字和已完成场景摘要，只承接、不复述；
4. 每段独立识别 provider 截断，全部成功才拼成一个候选；
5. 长正文改写按自然段切片，携带前段结尾、适用于本段的问题、全章审查摘要和用户意见；
6. token 与耗时按逻辑任务聚合，`modelCallCount` 记录实际计划调用次数。

15,000 字目标通常是五次正文调用。任何中段失败都会让整个逻辑任务失败，不会把半章正文写入候选或稿件。

## 4. 自动清理策略

这里的“自动清理”是“检测 → 给出可定位问题 → 定点改写 → 再审查”，不是对用户正文做危险的批量替换。

- Prompt 纪律：要求具体动作/对白/感官事实，限制连续“像/仿佛/似乎”，禁止清单式环境陈列、
  模板化微表情、空泛套话、模糊拐杖词、否定式排比、强行三段式、解释比喻和结尾强行升华；
- Style Critic：逐项检查主谓/动宾搭配、代词指向、成分残缺或赘余、同义反复、逻辑矛盾、视角外作者插话；
- 确定性兜底：未闭合/不匹配的对白引号直接阻塞；高密度类比标记、AI 腔词组、直陈情绪、空泛套话和重复句达到保守阈值时，强制
  `needs_rewrite`。模型即使把同一问题标为 minor 或总体判 pass，也不能绕过；
- 人工门：自动审查完成后仍由用户决定采用、按意见改写或重写一版。

这些指标用于发现明确退化模式，不是“AI 文本检测器”，也不能证明一篇小说自然、好看或具有个人风格。

## 5. 验证矩阵

| 层级             | 必测内容                                      | 通过标准                                     |
| ---------------- | --------------------------------------------- | -------------------------------------------- |
| 领域/IPC         | `chapterLength` 封闭 schema、范围、锁与 patch | 非法值拒绝，旧数据兼容                       |
| 抽取             | 中文数字、阿拉伯数字、范围、一章 15,000 字    | 全书章节数与单章字数不混淆                   |
| 蓝图             | `targetLength=1 chapter`                      | 模型多给章节时自动修复或失败                 |
| Task Engine      | 15,000 字 draft/rewrite                       | 五次调用，拼成一个约束内候选                 |
| Critic           | 模型 pass/minor 与硬门冲突                    | 硬门提升为 `needs_rewrite`                   |
| 产品真实模型门禁 | 3,000 字基准链路                              | 最终 2,700–3,300 字且无确定性 blocking issue |

## 6. PlotPilot 参考与 A/B

[PlotPilot（墨枢）](https://github.com/shenminglinyi/PlotPilot) 的公开 README（核对于 2026-08-14）把长篇能力
拆为结构化叙事状态、动态上下文、章节生产管线和质量监控：章节写作之后更新摘要/事件/三元组/伏笔，文风漂移
和陈词滥调命中后触发定向修写。这里采纳的是可验证的工作流原则：长文不依赖一次生成、规划与正文分离、
问题触发定点改写、状态写入有明确时机。不能仅凭其项目说明断言正文质量更好；对比必须使用本项目的同题盲评。

本批已落地篇幅结构化、长章节切片、硬质量门与定点改写。PlotPilot 中跨章摘要、事件流、伏笔注册表、语义检索
和相对作者样本的文风漂移仍属于下一阶段 Story State Ledger / Preference Profile，不能用本批的章内词面指标冒充。

下一轮实验固定同一题库和 provider 参数，每个 case 同时生成旧单次策略与新流水线候选，匿名随机排序，至少
两名独立评分者。继续阅读意愿、要求符合度、人物可信度、语言自然度、AI 味、剧情推进、简洁度和连续性分别
评分；报告均值、离散度、评分者一致性、字数达标率、自动改写次数、token 与耗时。至少覆盖：

- 3,000 字常规连载章；
- 一章完结、15,000 字；
- 强风格约束且禁用常见 AI 套话；
- 对话密集与氛围叙事各一例。

自动测试只防止机制退化。没有上述盲评证据前，不宣称“中文质量已超过 PlotPilot”或“AI 味已经解决”。
