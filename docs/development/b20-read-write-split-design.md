# B20 设计：读写分离——稿件阅读视图与编辑器自适应

> 背景：D13 评审坐实「手机看稿 = 打开编辑 textarea」（固定高度内滚动、双滚动条、
> 无只读形态）。B18 已把阅读排版权威（`.reading-prose`）建立在候选审阅上；本批把
> 「读」变成稿件的默认动作，并让编辑器只剩一层滚动。

## 1. 决策

### D-B20-1 稿件章节的默认动作是「阅读」

- 稿件章节行动作从单个「编辑」改为「阅读 / 编辑」两个显式入口，展开后「收起」。
- 阅读视图：权威正文（`chapter.title/content`，非编辑缓冲区）按 `.reading-prose`
  排版分段渲染 + 字数，底部「编辑这一章」原地切换编辑态。读是浏览权威内容，
  编辑是显式意图——与候选审阅（先读后决策）同一个心智模型。
- 持久化草稿横幅在两种模式下都显示（阅读时用户也应知道有未保存草稿；「恢复到
  草稿」写的是编辑缓冲区，切到编辑态即可见——行为与既有一致，不加分支）。

### D-B20-2 编辑器高度自适应，页面只有一层滚动

- textarea 去掉固定 `rows`，`useLayoutEffect` 按 `scrollHeight` 自适应高度
  （内容/章节切换时重算），`resize-none`＋最小高度兜底；长章节由页面滚动承载，
  消除「页面 + 文本框」双滚动条。
- jsdom 下 `scrollHeight` 恒 0，自适应不参与断言（浏览器实测覆盖）；行为面由
  「编辑态无 rows 固定高度」间接钉住。

## 2. 兼容性

- 既有 ManuscriptPanel 测试全部走「编辑」按钮直达编辑态——语义不变，零改动；
  新增阅读视图用例（默认阅读、编辑这一章切换、收起）。
- 候选审阅（CandidateView）不动——它已是阅读形态。

## 3. 不做什么

- 不做阅读进度记忆/翻页/字体调节（未来「阅读偏好」分区的事）；
- 不动自动保存/CAS/版本历史逻辑。

## 4. 验证基线

`pnpm check` 全绿；浏览器实测：桌面与 375pt 下点章节进阅读视图（reading-prose
排版）、编辑态输入时无内层滚动条、亮暗两色无回归。
